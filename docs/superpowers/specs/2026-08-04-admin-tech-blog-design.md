# 관리자 전용 기술 블로그 리팩터링 설계

## 목표

현재 Firebase 공개 게시판을 포트폴리오에 통합된 개인 기술 블로그로 전환한다. 방문자는 게시글을 읽기만 할 수 있고, 지정된 Google 계정 한 개만 관리자 화면에서 글을 작성·수정·삭제할 수 있다. 기존 Firestore `posts` 컬렉션과 게시글은 유지한다.

## 범위

### 포함

- Google 계정 관리자 로그인
- 단일 관리자 계정 판별
- 공개 블로그 목록과 상세 화면
- 관리자 게시글 목록
- 게시글 작성, 수정, 삭제
- 작성일 직접 지정과 수정
- 기존 `/board` 경로의 `/blog` 리다이렉트
- 모바일 내비게이션과 접근성 개선
- Firebase 초기화 실패와 Firestore 작업 오류 처리
- 타입 검사, ESLint, 빌드 및 핵심 로직 테스트

### 제외

- 초안과 예약 발행
- 댓글, 좋아요, 조회수
- 태그, 카테고리, 검색, 페이지네이션
- 다중 관리자와 역할 시스템
- 이미지 업로드
- 휴지통, 삭제 복구, 버전 이력
- 별도 Next.js API나 Firebase Admin SDK

## 아키텍처

기존 Firebase 클라이언트 SDK를 재사용한다. 공개 화면은 Firestore `posts` 컬렉션을 읽고, 관리자 화면은 Firebase Authentication의 Google 로그인을 사용한다. 화면의 관리자 가드는 UX를 위한 1차 경계이며, 실제 쓰기 보안은 Firestore Security Rules가 담당한다.

```text
공개 사용자
  /blog -> Firestore posts 읽기
  /blog/[id] -> Firestore posts/{id} 읽기

관리자
  /admin/login -> Google 로그인
  /admin/posts -> 게시글 관리
  /admin/posts/new -> 게시글 작성
  /admin/posts/[id]/edit -> 게시글 수정
                         -> Firestore Rules 확인
                         -> Firestore posts 쓰기
```

관리자는 Google 계정 이메일 한 개로 판별한다. 클라이언트는 Vercel의 `NEXT_PUBLIC_FIREBASE_ADMIN_EMAIL` 환경 변수와 로그인 계정을 비교해 권한 없는 화면 접근을 막는다. Firestore Rules에도 같은 관리자 이메일 조건을 적용해 브라우저 코드 우회 쓰기를 차단한다. 관리자 이메일은 비밀번호가 아니며, 실제 인증은 Firebase가 발급한 검증된 인증 토큰으로 판단한다.

## 라우트

### 공개 라우트

- `/blog`: 작성일 내림차순 게시글 목록
- `/blog/[id]`: 게시글 상세
- `/board`: `/blog`로 영구 리다이렉트
- `/board/[id]`: 같은 문서 ID의 `/blog/[id]`로 영구 리다이렉트
- `/board/new`: `/admin/posts/new`로 이동하되 인증되지 않은 사용자는 로그인 화면으로 보낸다.

### 관리자 라우트

- `/admin/login`: Google 로그인
- `/admin/posts`: 게시글 목록, 수정·삭제 진입, 로그아웃
- `/admin/posts/new`: 새 글 작성
- `/admin/posts/[id]/edit`: 기존 글 수정

관리자 링크는 공개 내비게이션에 노출하지 않는다.

## 데이터 모델

기존 문서와 호환되는 필드를 유지한다.

```ts
interface BlogPost {
  id: string;
  title: string;
  content: string;
  createdAt?: Timestamp;
  updatedAt?: Timestamp;
}
```

새 글은 `title`, `content`, 사용자가 지정한 `createdAt`을 저장한다. 수정 시 제목, 본문, 작성일을 변경할 수 있고 `updatedAt`은 서버 시간으로 자동 기록한다. 기존 글에 `createdAt` 또는 `updatedAt`이 없어도 목록과 상세 화면은 오류 없이 대체 문구를 표시한다.

작성일 입력은 브라우저의 `datetime-local`을 사용한다. 새 글에는 현재 현지 시간을 기본값으로 넣고, 저장 시 JavaScript `Date`를 Firestore `Timestamp`로 변환한다. 미래 날짜도 표시 날짜로 허용하지만 예약 발행으로 취급하지 않으며 저장 즉시 공개한다.

## 인증과 권한

인증 상태는 다음 네 상태로 관리한다.

1. 인증 확인 중
2. 로그인 필요
3. 로그인했지만 관리자 계정이 아님
4. 관리자 접근 허용

Google 로그인 성공 후 계정 이메일이 관리자 환경 변수와 일치해야 관리자 화면을 렌더링한다. 일치하지 않으면 권한 없음 안내와 로그아웃만 제공한다.

Firestore Rules 정책은 다음과 같다.

- `posts` 읽기: 모든 사용자 허용
- `posts` 생성·수정·삭제: 인증된 관리자 이메일만 허용
- 다른 컬렉션: 기존 규칙을 유지하되 이번 기능에서 권한을 확장하지 않음

저장소에는 현재 배포된 Firestore Rules가 없으므로 기존 Production Rules를 먼저 확인하고 백업한 다음 `posts` 규칙만 병합한다. 확인되지 않은 전체 규칙 파일로 Production 설정을 덮어쓰지 않는다.

Vercel Production, Preview, Development 환경에 Firebase 공개 설정과 관리자 이메일을 각각 설정한다. 환경 변수 변경 후에는 새 배포가 필요하다.

## 공개 UI·UX

기존 인디고·그레이 시각 스타일을 유지한다. `/blog`는 카드 장식보다 제목, 작성일, 본문 요약을 우선하는 목록으로 구성한다. 항목 전체를 클릭할 수 있게 하며 로딩, 빈 목록, 조회 실패를 구분한다.

상세 화면은 읽기 폭을 제한하고 제목, 작성일, 수정일, Markdown 본문과 목록 복귀 링크를 제공한다. 코드 블록은 모바일에서 가로 스크롤되며 본문 타이포그래피와 구문 강조 스타일을 실제로 불러온다.

공통 내비게이션에서 `게시판`을 `블로그`로 변경한다. 데스크톱에서는 현재 메뉴를 표시하고, 모바일에서는 메뉴 버튼으로 접고 펼친다. 링크 안에 버튼을 중첩하지 않으며 키보드 포커스와 `aria-current`를 제공한다.

## 관리자 UI·UX

로그인 화면에는 Google 로그인 동작 하나만 둔다. 게시글 관리 화면은 제목, 작성일, 수정·삭제 동작과 새 글 작성, 로그아웃을 제공한다. 데스크톱과 모바일 모두 같은 정보 우선순위를 유지하되 모바일에서는 세로 목록으로 표시한다.

작성·수정 폼 필드는 제목, 작성일, Markdown 본문 세 개다. 모든 필드는 명시적인 레이블을 가진다. 저장 중에는 제출 버튼을 비활성화하고 결과 메시지는 `role=status` 또는 `role=alert`로 전달한다.

삭제는 브라우저 기본 확인 대화상자로 재확인한다. Firestore 삭제가 성공한 뒤 목록에서 제거하며 실패하면 기존 항목을 유지하고 오류를 표시한다.

## 데이터 흐름

### 공개 목록

1. Firestore `posts` 문서를 읽는다.
2. 문서를 화면 모델로 변환한다.
3. 클라이언트에서 `createdAt` 내림차순으로 정렬하고 작성일이 없는 기존 문서는 마지막에 둔다.
4. 작성일이 없는 기존 문서는 안정적인 대체 문구를 사용한다.
5. 제목, 날짜, 본문 요약을 렌더링한다.

### 작성

1. 관리자 인증과 이메일을 확인한다.
2. 제목과 본문 공백, 유효한 작성일을 검증한다.
3. 지정 작성일을 `Timestamp`로 변환한다.
4. Firestore에 새 문서를 추가한다.
5. 성공 후 관리자 목록으로 이동한다.

### 수정

1. 문서를 읽고 폼 기본값으로 변환한다.
2. 동일한 입력 검증을 수행한다.
3. 제목, 본문, 작성일과 자동 `updatedAt`을 저장한다.
4. 성공 후 관리자 목록으로 이동한다.

### 삭제

1. 브라우저 확인 대화상자로 의도를 확인한다.
2. Firestore 문서를 삭제한다.
3. 성공 후 목록을 갱신한다.

## 오류 처리

- Firebase 설정 누락: 모듈 초기화 500 대신 해당 화면에 설정 오류 표시
- 로그인 팝업 취소: 일반 오류와 구분해 조용히 로그인 화면 유지
- 권한 없음: 관리자 계정이 아니라는 안내와 로그아웃 제공
- 목록 조회 실패: 오류와 재시도 동작 제공
- 문서 없음: 공개 상세는 404 성격의 안내, 관리자 수정은 목록 복귀 제공
- 작성·수정 실패: 입력값을 유지하고 재시도 허용
- 삭제 실패: 목록 항목을 유지하고 오류 표시

## 테스트와 검증

새 테스트 의존성을 최소화한다. 순수한 날짜 변환과 게시글 입력 검증은 Node 기본 테스트 러너로 검증한다. UI와 Firebase 통합 흐름은 개발 환경에서 로그인, 작성, 수정, 삭제, 공개 조회를 순서대로 확인한다.

각 구현 단계는 다음 검증을 통과해야 한다.

```bash
npx tsc --noEmit
npm run lint
npm run build
```

추가 핵심 검증:

- 관리자 이메일이 아닌 계정은 관리자 기능을 사용할 수 없음
- 로그아웃 사용자는 관리자 작성 URL에서 로그인 화면으로 이동
- 작성일을 변경해 저장하면 공개 목록 정렬과 표시가 반영됨
- 수정 후 `updatedAt`이 표시됨
- 삭제 취소 시 문서가 유지되고, 확인 시 삭제됨
- 기존 `posts` 문서가 그대로 목록과 상세에 표시됨
- `/board` 기존 링크가 새로운 블로그 경로로 이동함

## 단계별 구현 순서

1. 깨진 린트 명령과 Firebase 초기화로 인한 로컬 빌드 실패를 해결한다.
2. 공통 게시글 타입, 날짜 변환, 입력 검증을 테스트 우선으로 만든다.
3. Google 로그인과 단일 관리자 가드를 구현한다.
4. 관리자 게시글 목록과 작성·수정·삭제 기능을 구현한다.
5. 공개 게시판을 블로그 목록·상세 UI로 전환한다.
6. 기존 경로 리다이렉트와 공통 내비게이션의 모바일·접근성을 정리한다.
7. Firestore Rules, 환경 변수 문서, 전체 검증을 완료한다.

각 단계는 독립적인 커밋으로 남기며, 다음 단계로 넘어가기 전에 타입·린트·빌드 상태를 확인한다.
